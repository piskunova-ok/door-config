# Подготовка DOOR CONFIG к размещению

Ничего из этого файла не выполняется автоматически. Работайте только с отдельным Supabase-проектом DOOR CONFIG.

## Netlify

`netlify.toml` собирает Vite в `dist` и возвращает `index.html` для SPA-маршрута `/admin`. Сборка Netlify остановится, если не заданы публичные параметры Supabase.

В настройках **этого сайта** Netlify → Environment variables → Builds добавьте:

- `VITE_SUPABASE_URL` — `https://PROJECT_REF.supabase.co` отдельного проекта DOOR CONFIG;
- `VITE_SUPABASE_PUBLISHABLE_KEY` — его publishable key (или legacy anon key).
- `VITE_DOOR_REQUESTS_ENABLED` — `false` для демонстрационного запуска. При отсутствии переменной форма также скрыта.

Сверьте каталог с URL проекта в Supabase Dashboard. Netlify берёт публичные переменные из окружения сборки. URL функции указывается через `VITE_DOOR_REQUEST_URL`. Параметры отправки почты задаются на сервере.

До переключения базы разместите сборку **вместе с новыми и старыми изображениями**. Проверьте ответ 200 для нескольких `/images/catalog-2026/*.webp`, каталога и прямого открытия `/admin`. Не удаляйте `/images/doors/*.webp` до успешного переключения и проверки PDF.

## Локальная проверка заявок

Из корня репозитория установите зависимости обоих пакетов и выполните проверки. Для локальных тестов нужен Node.js 22.13+ либо 24. Серверная библиотека PDFKit устанавливается только для функции.

```powershell
npm ci
npm ci --prefix functions/submit-door-request
npm test
npm run build
npm run build:function
```

Тесты подставляют синтетические контакты, каталог и ответ Postbox. Обработчик читает пять таблиц публичного каталога с ключом publishable (или legacy anon), заново вызывает общий `calculateEstimate` и сверяет сумму и каждую ценовую позицию. При HTTP 409 браузер показывает новую смету. Пользователь отдельно подтверждает её, и функция снова проверяет цены. При удалённой опции, недоступности каталога или ошибке PDF отправка останавливается.

Команда `build:function` готовит рабочие файлы в `artifacts/door-request-function`. Для загрузки в консоль упакуйте перечисленные файлы из корня репозитория. Каждый файл должен лежать в корне ZIP.

```powershell
$functionFiles = 'index.js','handler.mjs','Manrope.ttf','OFL.txt','package.json','package-lock.json' |
  ForEach-Object { Join-Path 'artifacts/door-request-function' $_ }
Compress-Archive -LiteralPath $functionFiles -DestinationPath 'artifacts/door-request-function.zip' -Force
```

В архив входит полный [Manrope с лицензией SIL OFL](https://github.com/google/fonts/tree/main/ofl/manrope). Код формы, .env, контакты и node_modules в архив не входят. Cloud Functions установит production-зависимости по lock-файлу.

## Одна функция в Yandex Cloud

Следующие действия выполняет владелец после отдельного согласования размещения.

1. В облаке **cloud-gale-477** откройте каталог **door-config** и раздел **Cloud Functions**. Выберите функцию для заявок, если она уже создана. Иначе создайте одну функцию с именем `door-config-request`.
2. Создайте версию из локального ZIP. Среда **Node.js 22**, точка входа **index.handler**, начальные параметры **256 МБ** и **30 секунд**. Выберите сервисный аккаунт **postbox-user** с существующей ролью **postbox.sender**. Функция получает временный IAM-токен из контекста вызова.
3. Задайте переменные версии по таблице. Доступ на вызов с сайта предоставляется только этой функции через опцию публичного вызова. Оставьте серверный приём выключенным на этапе подготовки.
4. Скопируйте HTTPS-ссылку для вызова вида `https://functions.yandexcloud.net/<ID>` в переменную сборки Netlify `VITE_DOOR_REQUEST_URL`. Используется обычная HTTP-интеграция без параметра `integration=raw`. Оставьте `VITE_DOOR_REQUESTS_ENABLED=false`. Настройки каталога Netlify сохраняются.
5. После размещения выключенной версии проверьте OPTIONS с origin сайта и POST с пустым объектом: ожидаются 204 и 503. Проверять приём реальной заявки следует отдельно, после согласования и подготовки сведений об обработке данных. При разрешённом включении сначала переключается серверная версия, затем клиентская сборка. Для остановки приёма сначала выключается серверный флаг. Старый приём через Supabase Edge Function держите выключенным.

| Переменная функции | Значение |
|---|---|
| `DOOR_REQUESTS_ENABLED` | `false`. При отсутствии переменной приём также выключен. |
| `SITE_ORIGINS` | `https://door-config-piskunova-ok.netlify.app`. Для нескольких согласованных origin используйте запятую и точные адреса без завершающего слеша. |
| `SUPABASE_URL` | HTTPS URL действующего каталога DOOR CONFIG. |
| `SUPABASE_PUBLISHABLE_KEY` | Публичный ключ каталога с правом чтения по RLS. |
| `POSTBOX_FROM` | `requests@mail.okdigitalstudio.ru` |
| `POSTBOX_TO` | `piskunova.prof@mail.ru` |

Контакты и время подтверждения согласия получает менеджер в письме. PDF содержит смету. Функция держит данные в памяти на время запроса и не логирует тело. В Supabase уходят только GET-запросы чтения каталога. История прежних заявок в админке остаётся отдельной. На сервере действует лимит тела 16 КиБ, проверка формы-ловушки и времени заполнения. Лимит в восемь попыток в минуту по адресу источника действует в пределах одного прогретого экземпляра. Клиент предотвращает двойное нажатие. Сквозной дедупликации между экземплярами и очереди повторной отправки нет. При сетевом тайм-ауте проверьте почту менеджера перед ручным повтором. Успешный ответ означает приём Postbox, фактическая доставка проверяется в почтовом ящике.

## Переключение фотографий

После публикации и проверки 25 новых файлов вручную выполните в SQL Editor **только** [20261101000000_catalog_images_2026.sql](supabase/migrations/20261101000000_catalog_images_2026.sql). Скрипт сначала сверяет 20 строк и их старые или новые пути, затем меняет только `door_finishes.image_path` в транзакции. Цены и RLS не затрагиваются. При несоответствии транзакция прервётся; сначала разберите причину, не обходите проверку.

После применения обновите публичный каталог, проверьте пять моделей, по четыре отделки, смену фотографий, PDF выбранной комплектации и отсутствие ошибок загрузки.

Если после переключения обнаружена ошибка, выполните вручную [rollback_catalog_images_2026.sql](supabase/rollback_catalog_images_2026.sql) в том же проекте. Он сверяет 20 текущих строк и возвращает старые пути в одной транзакции. Старые WebP должны оставаться на сайте. После исправления причины можно повторно выполнить миграцию новых путей.

## Данные, необходимые до публичного сбора заявок

В проекте есть отдельный обязательный checkbox согласия и передача времени подтверждения согласия в письме менеджеру, но пока нет опубликованной политики обработки персональных данных и сведений об операторе. До включения публичного приёма заявок владелец должен предоставить действительные сведения об операторе (наименование/ФИО и контакт для обращений), определить цели и сроки обработки и хранения, список получателей/обработчиков и порядок обращения или отзыва согласия. Затем нужно разместить утверждённую политику и дать ссылку на неё рядом с checkbox. Также проверьте применимость уведомления Роскомнадзора и требования к месту хранения данных для выбранной инфраструктуры. Не подставляйте вымышленные реквизиты.

До выполнения этого шага проект **не готов к публичному сбору контактных данных**, даже если техническая отправка формы работает.
