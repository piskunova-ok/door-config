# Подготовка DOOR CONFIG к размещению

Ничего из этого файла не выполняется автоматически. Работайте только с отдельным Supabase-проектом DOOR CONFIG.

## Netlify

`netlify.toml` собирает Vite в `dist` и возвращает `index.html` для SPA-маршрута `/admin`. Сборка Netlify остановится, если не заданы публичные параметры Supabase.

В настройках **этого сайта** Netlify → Environment variables → Builds добавьте:

- `VITE_SUPABASE_URL` — `https://PROJECT_REF.supabase.co` отдельного проекта DOOR CONFIG;
- `VITE_SUPABASE_PUBLISHABLE_KEY` — его publishable key (или legacy anon key).
- `VITE_DOOR_REQUESTS_ENABLED` — `false` для демонстрационного запуска. При отсутствии переменной форма также скрыта.

Сверьте `PROJECT_REF` с URL проекта в Supabase Dashboard. Значения с префиксом `VITE_` включаются в клиентскую сборку: никогда не используйте здесь service-role key, `RESEND_API_KEY`, `REQUEST_IP_SALT` или другие секреты. Ключи Resend и `SITE_ORIGINS` принадлежат только окружению Supabase Edge Function. Netlify не читает локальный `.env.local` при облачной сборке.

До переключения базы разместите сборку **вместе с новыми и старыми изображениями**. Проверьте ответ 200 для нескольких `/images/catalog-2026/*.webp`, каталога и прямого открытия `/admin`. Не удаляйте `/images/doors/*.webp` до успешного переключения и проверки PDF.

## Демонстрационный режим и серверный приём заявок

Подготовленная версия `supabase/functions/submit-door-request/index.ts` проверяет серверный секрет `DOOR_REQUESTS_ENABLED`. Только точное значение `true` разрешает обработку POST; при отсутствии секрета и при `false` функция отвечает 503 до чтения контактов, записи расчёта и вызова Resend. Клиентская форма отдельно скрыта, пока `VITE_DOOR_REQUESTS_ENABLED` не равна `true`. Клиентский флаг не служит защитой сервера.

Перед демонстрационным запуском разверните **только** эту Edge Function в отдельный проект DOOR CONFIG, без SQL-миграций: `npx supabase functions deploy submit-door-request --project-ref YOUR_DOOR_CONFIG_PROJECT_REF --no-verify-jwt`. Сначала сверьте project ref с `VITE_SUPABASE_URL`. После развёртывания убедитесь, что `DOOR_REQUESTS_ENABLED` отсутствует или равен `false`; при возможности проверьте отклонение POST без персональных данных. Сейчас живую функцию не меняли, поэтому её действующее поведение нельзя считать отключённым. Не размещайте серверный переключатель в Netlify или клиентском коде.

Для будущего включения заявок после выполнения требований к персональным данным установите в секретах функции `DOOR_REQUESTS_ENABLED=true`, проверьте `SITE_ORIGINS` и Resend, затем пересоберите сайт с `VITE_DOOR_REQUESTS_ENABLED=true`. Код формы, RPC и админки сохранён. Выполните одну согласованную контрольную заявку и проверьте сохранение и письмо; если письмо не доставлено, интерфейс не должен заявлять об успешной отправке уведомления. При выключении сначала установите серверный флаг `false`, затем пересоберите клиент с `VITE_DOOR_REQUESTS_ENABLED=false`.

## Домен и заявки

После выбора фактического публичного домена добавьте его точный origin (схема + домен + при необходимости порт, без пути и завершающего `/`) в секрет `SITE_ORIGINS` **той же** Supabase Edge Function `submit-door-request`. Сохраните уже разрешённые origin, которые ещё нужны; при использовании обоих `www` и корневого домена перечислите оба. Не используйте `*`. Не помещайте `SITE_ORIGINS` в Netlify.

Без этого функция отклонит заявки с нового домена. После отдельного разрешения на проверку отправьте одну тестовую заявку и проверьте сохранённый расчёт, строку заявки в `/admin`, статус и фактическое получение письма. Сейчас автоматическая отправка тестовой заявки не выполнялась.

## Переключение фотографий

После публикации и проверки 25 новых файлов вручную выполните в SQL Editor **только** [20261101000000_catalog_images_2026.sql](supabase/migrations/20261101000000_catalog_images_2026.sql). Скрипт сначала сверяет 20 строк и их старые или новые пути, затем меняет только `door_finishes.image_path` в транзакции. Цены и RLS не затрагиваются. При несоответствии транзакция прервётся; сначала разберите причину, не обходите проверку.

После применения обновите публичный каталог, проверьте пять моделей, по четыре отделки, смену фотографий, PDF выбранной комплектации и отсутствие ошибок загрузки.

Если после переключения обнаружена ошибка, выполните вручную [rollback_catalog_images_2026.sql](supabase/rollback_catalog_images_2026.sql) в том же проекте. Он сверяет 20 текущих строк и возвращает старые пути в одной транзакции. Старые WebP должны оставаться на сайте. После исправления причины можно повторно выполнить миграцию новых путей.

## Данные, необходимые до публичного сбора заявок

В проекте есть отдельный обязательный checkbox согласия и серверное сохранение времени согласия, но пока нет опубликованной политики обработки персональных данных и сведений об операторе. До включения публичного приёма заявок владелец должен предоставить действительные сведения об операторе (наименование/ФИО и контакт для обращений), определить цели и сроки обработки и хранения, список получателей/обработчиков и порядок обращения или отзыва согласия. Затем нужно разместить утверждённую политику и дать ссылку на неё рядом с checkbox. Также проверьте применимость уведомления Роскомнадзора и требования к месту хранения данных для выбранной инфраструктуры. Не подставляйте вымышленные реквизиты.

До выполнения этого шага проект **не готов к публичному сбору контактных данных**, даже если техническая отправка формы работает.
