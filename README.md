# DOOR CONFIG

Визуальный конфигуратор входных дверей на React, TypeScript и Vite. Публичный каталог и тарифы загружаются из отдельного Supabase-проекта DOOR CONFIG; при недоступности базы старые локальные цены не подставляются.

## Локальный запуск

```sh
npm install
cp .env.example .env.local
npm run dev
```

В `.env.local` нужны `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` этого проекта. Они публичные по назначению; service-role key и ключ Resend в клиентский код не добавляются. `VITE_DOOR_REQUESTS_ENABLED` по умолчанию выключен: сайт показывает расчёт и PDF без полей контактов. Без настроенной базы доступен явно обозначенный локальный режим, а админка не имитирует сохранение.

Проверки: `npm test` и `npm run build`. Кнопка PDF открывает печать браузера с A4-сметой; в диалоге нужно выбрать «Сохранить как PDF».

## Каталог и цены

Пять моделей имеют по четыре наружные отделки. Новый комплект содержит 20 наружных и 5 внутренних WebP в `public/images/catalog-2026/`; старые файлы в `public/images/doors/` сохранены для перехода и отката. `src/data/imageManifest.ts` связывает изображения с моделями, `src/lib/pricing.ts` рассчитывает стоимость, а `src/data/marketReferences.ts` хранит отдельные ссылки на опубликованные рыночные ориентиры. Ориентиры не участвуют в расчёте и не означают сотрудничества с производителем.

Серверная функция `create_door_request` повторно рассчитывает стоимость по текущим тарифам перед сохранением неизменяемого снимка заявки. Отправка проходит через `submit-door-request` только при серверном `DOOR_REQUESTS_ENABLED=true`; по умолчанию запросы отклоняются до записи и письма. Код формы и админки сохранён для будущего включения. Письмо администратору возможно только при корректно настроенном Resend и подтверждается отдельно. PDF-вложения в письме нет.
