# Supabase-проект DOOR CONFIG

Ниже описана установка в **новом чистом окружении**. В действующем отдельном проекте DOOR CONFIG миграции каталога и заявок уже выполнялись вручную; не повторяйте их ради подготовки сайта к публикации. Секретов в репозитории нет.

1. Создайте проект DOOR CONFIG в Supabase Dashboard.
2. В SQL Editor этого проекта выполните один раз `migrations/20261028000000_catalog_admin.sql`, затем `seed.sql`. Повторный запуск `seed.sql` не создаёт дубликаты и не перезаписывает изменения администратора.
3. В Authentication → Users создайте пользователя администратора и скопируйте его UUID. В SQL Editor выполните:

   ```sql
   insert into public.door_admins (user_id)
   values ('UUID_СОЗДАННОГО_ПОЛЬЗОВАТЕЛЯ')
   on conflict (user_id) do nothing;
   ```

4. Скопируйте `.env.example` в `.env.local` в корне проекта. Заполните `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` из **этого** проекта. Не добавляйте в клиент secret или service role key. Перезапустите `npm run dev`.
5. Откройте `/admin` и войдите созданным пользователем. Для новой модели сначала сохраните её скрытой, добавьте отделку, затем включите видимость.

До подключения базы публичная часть явно помечена как локальный режим. Когда оба параметра Supabase заданы, каталог читается из базы. При ошибке загрузки пользователь видит сообщение и кнопку повтора; старые локальные цены не подставляются. После сохранения правок публичная вкладка получает новые данные при открытии или возвращении фокуса.

RLS разрешает анонимным посетителям только чтение опубликованных моделей, отделок и тарифов. Запись разрешена только авторизованным пользователям, чей UUID добавлен в `door_admins`. Даже при прямом обращении к Data API обычный посетитель не может менять цены. Панель не создаёт новых аккаунтов и не использует секретный ключ.

При размещении статической сборки настройте возврат `index.html` для маршрута `/admin`, как для обычного Vite SPA.

Новые 25 изображений подключены локально. Порядок размещения файлов, последующего применения миграции путей и отката описан в [LAUNCH.md](../LAUNCH.md). Не применяйте `20261101000000_catalog_images_2026.sql` до публикации изображений.

## Заявки и уведомления (отдельное подключение)

Не применяйте миграцию к другому проекту и не запускайте её без проверки выбранного проекта. В SQL Editor **того же отдельного проекта DOOR CONFIG** после миграции каталога выполните `migrations/20261031000000_estimates_requests.sql` один раз. Она добавляет только `door_estimates`, `door_requests` и серверную функцию `create_door_request`; каталог и цены не меняет. Анонимным пользователям запрещены чтение и запись заявок. Администраторы читают заявки и меняют только статус.

Разверните Edge Function `submit-door-request` с отключённой встроенной JWT-проверкой (посетители не входят в систему):

```sh
supabase functions deploy submit-door-request --project-ref YOUR_DOOR_CONFIG_PROJECT_REF --no-verify-jwt
```

В настройках **Edge Function этого проекта** добавьте секреты:

- `DOOR_REQUESTS_ENABLED` — оставьте отсутствующим или установите `false` для демонстрационного запуска; только `true` разрешает создание заявок и отправку уведомлений;
- `SITE_ORIGINS` — точные адреса сайта через запятую, например `http://localhost:5173,https://your-domain.example` без завершающего `/`;
- `REQUEST_IP_SALT` — случайная длинная строка для хеширования IP при ограничении частоты заявок;
- `RESEND_API_KEY` — ключ Resend;
- `RESEND_FROM_EMAIL` — подтверждённый в Resend адрес отправителя;
- `ADMIN_NOTIFICATION_EMAIL` — адрес администратора, получающего заявки.

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` доступны функции из окружения Supabase. Секреты не помещайте в `.env.local` Vite или клиентский код. Инструкция по последовательности демонстрационного запуска и будущего включения формы — в [LAUNCH.md](../LAUNCH.md). Только после включения заявок и отдельного разрешения на контрольную отправку проверьте строку в `door_requests`, связанный снимок в `door_estimates`, отображение в `/admin` и фактическое получение письма. Пока Resend не настроен или письмо не доставлено, заявка сохраняется, а интерфейс не заявляет об отправке уведомления.

PDF создаётся существующей браузерной печатью после сохранения заявки и содержит подтверждённые сервером номер и строки сметы. PDF-вложения в email пока нет: для него потребуется отдельная серверная генерация PDF из сохранённого снимка расчёта и передача файла в Resend.
